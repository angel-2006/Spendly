# Spec: Registration

## Overview
Make the existing registration page functional. Today `GET /register` only renders a form that posts nowhere. This step adds `POST /register`, which validates the submitted name, email and password, stores a new user with a hashed password, and sends the visitor on to the login page. It is the first write path into the `users` table created in Step 1, and it must exist before login (Step 3) can authenticate anyone.

## Depends on
- Step 1 — Database setup (`users` table, `get_db()`, `init_db()`).

## Routes
- `GET /register` — render the registration form (already implemented, unchanged) — public
- `POST /register` — validate input, create the user, redirect to `login` on success; re-render `register.html` with an error message on failure — public

The `register` view function handles both methods via `methods=["GET", "POST"]`.

## Database changes
No database changes. The `users` table already has `name`, `email` (UNIQUE), `password_hash` and `created_at`.

New helpers in `database/db.py` (DB logic must not live in the route):
- `get_user_by_email(email)` — return the matching `sqlite3.Row` or `None`.
- `create_user(name, email, password)` — hash the password with `generate_password_hash`, insert the row with a parameterised query, return the new user id. Raise `sqlite3.IntegrityError` if the email already exists (the UNIQUE constraint is the source of truth, which also covers the race between a check and an insert).

## Templates
- **Create:** none
- **Modify:** `templates/register.html`
  - Change `action="/register"` to `action="{{ url_for('register') }}"` (hardcoded URLs are not allowed).
  - Re-populate `name` and `email` after a failed submission. Never re-populate the password.
  - Add `minlength="8"` to the password input to match the placeholder.
  - Keep the existing `{% if error %}` block for displaying errors.

- `database/db.py` — add `get_user_by_email()` and `create_user()`.
- `templates/register.html` — as described above.
- `CLAUDE.md` — update the implemented-routes table to show `POST /register` as implemented.

## Files to create
None.

## New dependencies
No new dependencies. `werkzeug.security` is already in `requirements.txt`, and `pytest` and `pytest-flask` are already listed.

## Validation rules
Applied in the route, in this order. The first failure re-renders the form with HTTP 200 and an error message.
1. `name` — strip whitespace; required.
2. `email` — strip whitespace and lowercase; required; must contain `@` with non-empty text on both sides (a simple check, no regex library).
3. `password` — required; at least 8 characters.
4. Email must not already be registered. Catch `sqlite3.IntegrityError` from `create_user()` and show "An account with that email already exists." Do not leak anything else about existing accounts.

On success: `redirect(url_for("login"))`. There are no sessions yet (Step 3), so the user is not logged in automatically and no `secret_key` or flash messaging is introduced in this step.

## Rules for implementation
- No SQLAlchemy or ORMs
- Parameterised queries only — never f-strings in SQL
- Passwords hashed with werkzeug (`generate_password_hash`); never store or log the plaintext
- Use CSS variables — never hardcode hex values
- All templates extend `base.html`
- DB logic lives in `database/db.py` only; the route just reads the form, calls helpers, and renders or redirects
- Use `url_for()` for every internal link and redirect
- Do not implement any stub route (`/logout`, `/profile`, `/expenses/...`) in this step
- Do not change the port (5001)
- Emails are stored lowercased so the UNIQUE constraint is effectively case-insensitive

## Definition of done
- [ ] `python app.py` starts on port 5001 without errors
- [ ] `GET /register` still renders the form, and the form's action is generated by `url_for`
- [ ] Submitting a valid name, new email and 8+ character password creates a row in `users` and redirects to `/login`
- [ ] The stored `password_hash` is a werkzeug hash, not the plaintext password
- [ ] Registering the same email again (including with different letter case) re-renders the form with an "already exists" error and creates no second row
- [ ] Empty name, empty or malformed email, and a password shorter than 8 characters each re-render the form with a clear error and create no row
- [ ] After a failed submission the name and email fields keep their values and the password field is empty
- [ ] The demo user (`demo@spendly.com`) is unaffected
- [ ] `pytest tests/test_registration.py` passes, covering success, duplicate email, each validation failure, and the password being hashed
